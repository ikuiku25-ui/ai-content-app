# AI学習コンテンツ配信PWA — フェーズ1「土台づくり」設計書

作成日: 2026-08-02

## 1. 目的

AI初心者向けの学習コンテンツを配信するPWAを作る。フェーズ1では、アプリとして
インストールでき、オフラインでも起動できる「土台」だけを完成させる。コンテンツ本体、
決済、GAS連携は後続フェーズで扱う。

### フェーズ1の完了条件

- ブラウザからインストール可能な状態になっていること（PC Chromeで検証）
- Service Workerが登録され、オフラインでもトップページが表示されること
- 仮トップページに「準備中」が表示されること
- ローカルサーバーで起動できること

### フェーズ1でやらないこと

- コンテンツ本体の作成・表示
- 決済処理、GASバックエンド
- 認証・購入者判定
- 本番ホスティングへの公開

## 2. 技術構成

ビルドツールを使わない素のHTML/CSS/JavaScriptで作る。

理由: フェーズ1の成果物は静的ファイル10個程度であり、ビルド工程を挟むと
node_modulesと設定ファイルの管理コストが成果物を上回る。将来GASと連携する際も
`fetch` だけで済むため、フレームワークを前提にする必要がない。Service Workerと
manifestの中身が直接見えることは、この段階では学習・デバッグ上の利点でもある。

## 3. フォルダ構成

公開ディレクトリ（サーバーに置くもの）と開発用ファイル（置かないもの）を分離する。
`ai-content-app/` をそのままホスティングのルートに載せれば公開できる。

```
My project/
├── ai-content-app/          公開ディレクトリ
│   ├── index.html           仮トップページ
│   ├── offline.html         オフライン時のフォールバック画面
│   ├── manifest.json        PWA設定
│   ├── sw.js                Service Worker
│   ├── README.md            起動・確認手順
│   ├── assets/
│   │   ├── css/style.css
│   │   ├── js/app.js        SW登録・インストール導線
│   │   └── icons/           PWAアイコン一式
│   └── content/             将来のコンテンツ置き場（現在は空）
├── tools/
│   └── generate-icons.mjs   仮アイコン生成スクリプト（公開しない）
└── docs/superpowers/specs/  設計ドキュメント
```

`sw.js` はルート直下に置く。Service Workerは自身が置かれた階層以下しか制御できない
ため、サブディレクトリに置くとアプリ全体をオフライン化できなくなる。

## 4. manifest.json

| 項目 | 値 | 根拠 |
|---|---|---|
| `name` | はじめてのAI学習 | 仮称。後から変更可能 |
| `short_name` | AI学習 | ホーム画面のアイコン下に表示される |
| `start_url` / `scope` | `./` | 相対パスにすることで、GitHub Pagesのサブディレクトリ配信でも独自ドメインのルート配信でも同じファイルが動く |
| `display` | `standalone` | URLバーを消し、アプリらしい見た目にする |
| `theme_color` | `#4F46E5` | インディゴ。学習用途に合う親しみと信頼のバランス |
| `background_color` | `#FFFFFF` | 起動時スプラッシュの背景 |
| `lang` | `ja` | |
| `orientation` | `any` | PC・タブレットでも使うため固定しない |

### アイコン

既存素材がないため、依存ゼロのNodeスクリプトでPNGを生成する。テーマカラーの背景に
白のノード図（AIを想起させる幾何マーク）を描く。

- `icon-192.png` (192×192, purpose: any)
- `icon-512.png` (512×512, purpose: any)
- `icon-maskable-512.png` (512×512, purpose: maskable) — Androidの円形・角丸マスクで
  切れないよう、図柄を中央80%のセーフゾーン内に収める
- `apple-touch-icon-180.png` (180×180) — iOSはmanifestのiconsを参照しないため別途必要
- `favicon-32.png` (32×32)

## 5. Service Worker

### キャッシュ設計

最初からキャッシュを2つに分ける。フェーズ3で「決済完了後にコンテンツをダウンロード」を
実装する際、コンテンツだけを個別に追加・削除できるようにするため。

- `ai-content-app-shell-v1` — HTML・CSS・JS・アイコン。インストール時に一括保存
- `ai-content-app-content-v1` — コンテンツ本体。フェーズ1では空

キャッシュ名にバージョン番号を含め、`activate` 時に一覧にないキャッシュを削除する。

### 通信の扱い

1. **ページ遷移（navigate）** — ネットワーク優先。失敗時はキャッシュ、それも無ければ
   `offline.html`。表示内容が常に最新になる
2. **同一オリジンの静的アセット** — キャッシュ優先。無ければ取得してキャッシュに追加。
   表示が速くなる
3. **クロスオリジン通信** — Service Workerが介入せず素通しする。将来のGAS APIや
   決済プロバイダへのリクエストをキャッシュで壊さないため
4. **GET以外のリクエスト** — 介入しない

`install` で `skipWaiting()`、`activate` で `clients.claim()` を呼び、更新を即時反映する。
フェーズ1では更新通知UIを作らないため、挙動を単純に保つことを優先する。

## 6. 仮トップページ

「準備中」を表示する。加えて動作確認に必要な最小限の要素を持つ。

- Service Workerの登録状態を画面に表示する（デバッグ用）
- `beforeinstallprompt` を捕捉し、インストール可能になったらボタンを表示する
- iOS Safariでは `beforeinstallprompt` が発火しない仕様のため、iOSを検出したときは
  「共有 → ホーム画面に追加」の手順テキストを表示する
- 既にインストール済みで起動している場合（`display-mode: standalone`）はその旨を表示する

## 7. ローカル検証

Python標準機能で静的サーバーを起動する（追加インストール不要）。

```
cd ai-content-app && python3 -m http.server 8080
```

### 制約: 実機iPhoneでの確認はフェーズ1では行わない

Service Workerは `localhost` またはHTTPSでしか動作しない。同一Wi-Fi内の
`http://192.168.x.x` でiPhoneから開いてもPWAとしては動作しない。

したがってフェーズ1ではPC Chromeでのインストール確認までを完了条件とし、
iPhone実機での「ホーム画面に追加」の確認は、HTTPS環境へ公開したあと
（フェーズ2以降）に行う。公開先の選定は次フェーズの検討事項とする。

## 8. 後続フェーズへの引き継ぎ

- ホスティング先の選定とHTTPS公開（iPhone実機検証はここで可能になる）
- コンテンツ1本の作成と表示画面
- GASバックエンドの実装（購入者判定API）
- 決済完了後に `content-v1` キャッシュへコンテンツを保存する処理
