## 1. 目的

無料記事を1本しか扱えない現状を改め、複数の記事を並べられるようにする。
無料記事の題材は「どんな生成AIがあって、何ができるか」の全体像と、その各論。
読者はAIをまったく触ったことがない人で、中学生にも分かる平易さを目標とする。

### 完了条件

- トップページに記事の一覧が出る
- `content.html?id=<記事ID>` で任意の記事が開く
- 目次にないIDを指定してもファイルを読ませない
- 一覧に載っている記事とその図解が、インストール時にすべて保存される
- オフラインで、一覧からどの記事も開ける
- 有料記事の動作は変わらない

### やらないこと

- 記事の検索・タグ・並び替え
- 記事間の「前へ／次へ」移動
- 有料記事側の複数対応（今も1本前提のまま）

## 2. 無料と有料の線引き

無料記事では「**何があって、何ができるか**」まで出し切る。産業地図にあたる部分を
出し惜しみしない。

有料記事は「**実際にどう使いこなすか**」で差別化する。指示の出し方、うまくいかない
ときの直し方、失敗例、具体的な手順。無料が充実しているほど信用され、有料へ進みやすい。

## 3. 記事データの持ち方

記事1本がJSONファイル1つ。それとは別に目次ファイルを置く。

```
content/
├── index.json          記事の一覧（並び順・タイトル・要約）
├── what-is-ai.json     記事本体
├── services-map.json   記事本体
└── figures/            図解（SVG）
```

### `content/index.json`

```json
{
  "articles": [
    { "id": "what-is-ai", "title": "…", "summary": "一覧に出す1〜2行の紹介" }
  ]
}
```

並び順は配列の順とする。記事を増やすときは、記事のJSONを1つ足して目次に1行加える。

### 記事IDの付け方

`lesson-01` のような通し番号ではなく、`what-is-ai` のように内容が分かる名前にする。
番号は記事を間に差し込んだ時点で嘘になり、URLからも内容が読み取れないため。

既存の `lesson-01.json` は `what-is-ai.json` へ移行する。この記事は動作確認用に
書いたものだが、AI・機械学習・生成AIの関係を扱っており、まったくの初心者にとっては
全体像記事の前段として役立つので残す。

## 4. 画面

### トップページが一覧を兼ねる

一覧専用ページを別に作らず、トップページに記事を並べる。ページ数とタップ数が減り、
迷いにくい。現在のトップページは「準備中」の表示とボタン2つだけで、実質空いている。

記事が増えて一覧が長くなったら、そのとき専用ページへ分ける。

### 記事ページ

`content.html?id=<記事ID>` で開く。画面と描画の作りは変えず、読み込む先だけが変わる。
描画は既存の `render-article.js` をそのまま使う。

## 5. IDの検証

`?id=` はURLに現れるため誰でも書き換えられる。**目次に載っているIDだけを受け付ける。**
一致しないIDや、IDの指定がない場合は、トップページへ戻す。

目次と突き合わせずに `content/<id>.json` を組み立てて取得すると、`../` を含むIDで
意図しないファイルを読ませる余地が生まれる。取得先は必ず目次にある記事から決める。

## 6. オフライン対応

`sw.js` の `CONTENT_ASSETS` に、目次ファイル・全記事のJSON・全図解を並べ、
インストール時にまとめて保存する。

記事が増えるとこの登録漏れが起きやすい。既存の `tools/check-offline-precache.mjs` を
拡張し、**目次に載っている全記事とその図解が保存対象に入っているか**を検査する。
漏れがあればコマンドが失敗するので、公開前に気づける。

有料記事は従来どおり、解錠時にGASから取得してキャッシュへ保存する。この経路は変えない。

## 7. 記事の構成（予定）

仕組みはこの一覧に依存しないが、想定として記録しておく。

1. `what-is-ai` — AIってなに？（既存を移行）
2. `services-map` — どんな生成AIがあるのか（全体像／今回の主題）
3. 以降、分野ごとの各論（文章・画像・音声・動画など）

各論を「サービスごと」ではなく「分野ごと」にまとめ、その中で代表的なサービスを紹介する
案を推す。サービス単位だと本数が増えるうえ、個々の製品の変化に記事が振り回されるため。
ただしこれは執筆時に改めて相談する。

## 8. 執筆時の注意

- **サービス名は公開前にWeb検索で現況を確認する。** 生成AIは変化が速く、Claudeの知識は
  最新とは限らない
- **バージョン番号と料金は書かない。** すぐ古くなり、記事の手入れが増える
- 中学生に通じる言葉を使う。専門用語を出すときは、その場で言い換えを添える

## 9. 今日の範囲

全体像記事（`services-map`）の執筆はその後に着手し、進んだところまでとする。
