# AI学習コンテンツ配信PWA — フェーズ3「解錠の仕組み」設計書

作成日: 2026-08-03
前提: [フェーズ1設計書](2026-08-02-ai-content-pwa-phase1-design.md) /
[フェーズ2設計書](2026-08-02-ai-content-pwa-phase2-design.md)

## 1. 目的

購入者だけが有料コンテンツを読める仕組みを作る。購入者にはコードを渡し、アプリで
入力すると本文がダウンロードされ、以後オフラインで読めるようにする。

### 完了条件

- 有効なコードで解錠でき、有料記事が表示される
- 解錠後、機内モードでも記事が読める
- 存在しないコード・無効化されたコードは拒否される
- 上限台数を超えた端末からの解錠は拒否される
- スプレッドシートからコードの行を消すと、新規の解錠ができなくなる

### やらないこと

- 決済サービスとの接続（フェーズ4）。今回はコードを手動で発行する
- ログイン・アカウント管理
- 独自ドメインの設定

## 2. 前提と限界

**ブラウザに表示できる内容のコピーは防げない。** 目指すのは完全な保護ではなく、
「支払わずに読むほうが面倒」という状態である。この前提のもとで以下を受け入れる。

- 購入者が本文をコピーして配ることは防げない
- 一度ダウンロードされた本文は遠隔で削除できない。コードを無効化しても、保存済みの
  端末では読める。無効化が効くのは次回以降のダウンロード
- 端末数の上限は厳密ではない。ブラウザのデータを消せば端末IDは変わる。
  気軽な使い回しを面倒にするための措置である

**GASのURLは公開リポジトリのJavaScriptに含まれ、誰でも見られる。** これは問題ない。
URLは秘密ではなく、鍵はコードだからである。有効なコードがなければ本文は返らない。

## 3. データの置き場所

Googleスプレッドシート1つに、シートを3枚作る。すべてユーザーが画面上で編集できる。

### `codes` — 発行済みコードの台帳

| 列 | 内容 |
| --- | --- |
| `code` | 発行コード（例: `AI-7K3M-9QP2-XR4T`） |
| `status` | `有効` / `無効`。`有効` 以外はすべて拒否する |
| `maxDevices` | 解錠できる端末数の上限。空欄なら3 |
| `note` | 誰に売ったかなどのメモ（システムは参照しない） |
| `issuedAt` | 発行日 |

拡散されたコードは、行を消すか `status` を `無効` にすれば止まる。

### `activations` — 使用履歴（自動で増える）

| 列 | 内容 |
| --- | --- |
| `code` | 対象のコード |
| `deviceId` | 端末を識別する乱数（個人情報は含まない） |
| `firstUsedAt` | 最初に解錠した日時 |
| `lastUsedAt` | 最後に通信した日時 |

### `article` — 有料記事の本文

1行が1ブロックに対応する。ユーザーがここを編集すれば、次回のダウンロードから反映される。

| 列 | 内容 |
| --- | --- |
| `type` | `title` / `subtitle` / `heading` / `paragraph` / `list` / `figure` / `note` |
| `text` | 本文（`title`・`subtitle`・`heading`・`paragraph`・`note` で使う） |
| `items` | 箇条書きの項目。セル内改行で区切る（`list` で使う） |
| `src` | 図解のGoogleドライブ ファイルID（`figure` で使う） |
| `caption` | 図解の説明（`figure` で使う） |

`title` と `subtitle` は記事のメタ情報として扱い、本文ブロックには含めない。
未知の `type` は無視する。将来ブロック種別が増えても古いアプリが壊れないようにするため。

有料記事の図解はGoogleドライブに置く。リポジトリは公開されているため、
有料の図解をリポジトリに置くことはできない。

## 4. GAS側（バックエンド）

### 窓口

`doPost` 1つ。リクエストは `{ action, code, deviceId }` のJSON文字列。

**送信時のContent-Typeは `text/plain` とする。** GASは事前確認の通信（CORSプリフライト）に
応答できず、`application/json` で送ると通信が失敗するため。GASを使う場合の定石である。

### action

| action | 動作 | 成功時の応答 |
| --- | --- | --- |
| `unlock` | コードを検証し、通れば記事全体を返す | `{ ok: true, article: {...} }` |
| `check` | コードがまだ有効かだけを確かめる | `{ ok: true, valid: true }` |

失敗時は `{ ok: false, error: <種別>, message: <日本語の説明> }` を返す。
`error` の種別は `bad_request` / `invalid_code` / `revoked` / `device_limit` / `server_error`。

### unlock の判定順序

1. `code` と `deviceId` があるか → なければ `bad_request`
2. `codes` に該当行があるか → なければ `invalid_code`
3. `status` が `有効` か → 違えば `revoked`
4. `activations` に同じ `code` と `deviceId` の組があるか
   - **ある** → 再ダウンロードとみなし、`lastUsedAt` を更新して通す
   - **ない** → そのコードの登録端末数を数え、`maxDevices` 以上なら `device_limit`。
     未満なら行を追加して通す
5. `article` シートを読んで記事を組み立て、返す

判定4は「同じ端末での再ダウンロードは何度でも許すが、新しい端末は上限まで」という意味になる。

### 図解の扱い

`figure` ブロックの `src` はGoogleドライブのファイルIDである。GASがファイルを読み、
データURI（`data:image/png;base64,...`）に変換して返す。画像をアプリへ直接渡すことで、
ドライブを公開せずに済む。読めないファイルIDはそのブロックごと省略する。

### コード発行の補助

スプレッドシートを開くとメニュー「AI学習アプリ」が追加され、「コードを発行」を選ぶと
`codes` に新しい行が1つ増える。コードは紛らわしい文字（0とO、1とIとL）を除いた
30種類の文字から12桁を生成し、`AI-XXXX-XXXX-XXXX` の形式にする。手作業での発行を
簡単にするためのもので、システムの動作には必須ではない。

## 5. アプリ側

### 画面

**`premium.html`（新規）** — 1枚で2つの状態を持つ。未解錠ならコード入力欄、
解錠済みなら記事本文。画面遷移を減らし、解錠直後にそのまま読み始められるようにする。

### ファイル分割

| ファイル | 役割 |
| --- | --- |
| `assets/js/render-article.js`（新規） | ブロック配列からDOMを組み立てる。取得元を問わない |
| `assets/js/content.js`（変更） | 無料サンプルをリポジトリから読む |
| `assets/js/premium.js`（新規） | 解錠の操作とGASとの通信、有料記事の読み込み |
| `assets/js/config.js`（新規） | GASのURLを1か所にまとめる |

描画処理を `render-article.js` に切り出し、無料サンプルと有料記事で共有する。
現在 `content.js` にある描画部分の移動であり、無料サンプルの動作は変わらない。

### 保存

| 保存先 | 内容 |
| --- | --- |
| `localStorage` の `aiapp.deviceId` | 端末を識別する乱数（初回に生成） |
| `localStorage` の `aiapp.unlockedCode` | 解錠に使ったコード |
| `content-v1` キャッシュ | ダウンロードした記事本文 |

記事は `content/premium-article.json` というURLでキャッシュに保存する。サーバー上に
実在しないURLだが、`content/` 以下に置くことでフェーズ2で作ったキャッシュ振り分けと
削除処理がそのまま適用される。

### 起動時の判定

1. キャッシュに記事があれば、それを表示する（オフラインでも読める）
2. なければ、保存済みコードで自動的にダウンロードを試みる
3. それも無ければ、コード入力欄を出す

オンラインで記事を表示する際、`check` でコードの有効性を確認する。無効化されていた場合は
**次回以降のダウンロードを止めるだけ**で、表示中の内容は消さない。既に読める状態のものを
突然消すと、通信の一時的な失敗と区別がつかず、正当な購入者の体験を損なうため。

### エラー表示

| 状況 | 表示 |
| --- | --- |
| `invalid_code` | コードが違う旨と、入力し直しの案内 |
| `revoked` | このコードは使えなくなっている旨と、問い合わせの案内 |
| `device_limit` | 上限台数に達している旨と、上限数 |
| 通信失敗 | 通信状況を確認する案内 |

## 6. 検証方法

Google側の準備が整う前にアプリ側を検証できるよう、**GASと同じ応答を返す確認用サーバー**を
`tools/mock-gas-server.mjs` に作る。依存ライブラリなしのNodeスクリプトで、公開対象の
`ai-content-app/` には含めない。

これにより、有効なコード・無効なコード・上限超過・通信失敗の各経路を、Googleの設定を
待たずに確認できる。本番URLが決まったら `config.js` を差し替え、実際のGASに対して
再検証する。
