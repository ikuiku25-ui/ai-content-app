# AI学習コンテンツ配信PWA — フェーズ2「公開とコンテンツ画面」設計書

作成日: 2026-08-02
前提: [フェーズ1設計書](2026-08-02-ai-content-pwa-phase1-design.md)

## 1. 目的

フェーズ1で作った土台をHTTPSで公開し、iPhone・Android・PCの実機でインストールと
オフライン動作を確認する。あわせて、コンテンツを表示する画面を作る。

### 完了条件

- `https://<ユーザー名>.github.io/ai-content-app/` でアクセスできること
- `git push` でサイトが自動更新されること
- PC Chromeでインストールとオフライン動作が確認できること（担当: Claude）
- iPhone Safariで「ホーム画面に追加」とオフライン起動ができること（担当: ユーザー）
- サンプルコンテンツ（テキスト＋図解＋画面例）が表示されること

### やらないこと

- 決済処理、GASバックエンド、購入者判定
- 本番コンテンツの執筆
- 独自ドメインの設定

## 2. 前提となる制約: リポジトリは公開になる

GitHub Pagesを無料で使うにはリポジトリをpublicにする必要がある（privateリポジトリでの
Pagesは有料プラン）。したがってリポジトリに置いたファイルは誰でも読める。

**この制約はフェーズ3の設計を拘束する。有料コンテンツの本文をリポジトリに置いてはならない。**
決済を経由しなくてもリポジトリを直接見れば全文が読めてしまうため。フェーズ3では、
有料コンテンツはリポジトリに含めず、購入者だけがGAS経由で取得する形にする。

フェーズ2で扱うのは動作確認用のサンプルなので、公開されて問題ない。

## 3. 公開の仕組み

### 認証

`gh`（GitHub公式CLI）をHomebrewで導入し、`gh auth login` のブラウザ認証で接続する。
認証操作はユーザー自身が行い、Claudeはパスワードもトークンも扱わない。

### デプロイ方法: GitHub Actions

リポジトリ直下には `ai-content-app/`・`tools/`・`docs/` がある。GitHub Pagesが標準で
公開できるのはリポジトリ直下か `/docs` のみで、どちらを選んでも設計書や開発用スクリプトが
公開されてしまう。

そのため `.github/workflows/deploy.yml` で `ai-content-app/` だけをPagesへ配信する。
`main` ブランチへのpushで自動実行する。

公開URLは `https://<ユーザー名>.github.io/ai-content-app/` となり、サブディレクトリ配信に
なる。フェーズ1で `start_url`・`scope`・各アセットのパスをすべて相対パスにしてあるため、
変更なしで動作する。

## 4. コンテンツ表示画面

### ページ構成

`content.html` を1枚追加する。単一ページ内で切り替えるのではなく別ページにすることで、
フェーズ1で作ったService Workerのページ遷移処理（ネットワーク優先＋オフライン代替）が
そのまま適用される。

トップページに「サンプルを読む」リンクを置く。

### データと表示の分離

本文を `content.html` に直接書かず、`content/lesson-01.json` から読み込んで描画する。

理由: フェーズ3で取得先をGASに変更する際、描画側を書き換えずにデータ供給元だけを
差し替えられるようにするため。表示を作り込んでから中身を差し替える順序だと、
描画とデータ構造が絡まって手戻りが出る。

JSONは種類つきのブロック配列とする。

| type | 用途 |
| --- | --- |
| `heading` | 見出し |
| `paragraph` | 本文 |
| `list` | 箇条書き |
| `figure` | 図解・スクリーンショット（画像＋キャプション） |
| `note` | 補足の囲み |

### 描画時の安全性

DOMへの流し込みには `textContent` を使い、`innerHTML` を使わない。フェーズ3では
このデータが外部（GAS）から来るため、HTMLとして解釈させると受け取った文字列が
そのままスクリプトとして動く危険がある。最初から安全な書き方に固定しておく。

### 図解の形式

図解・画面例はSVGで作る。テキストを含む図をPNGで生成するにはフォント処理が必要になるが、
SVGならテキストをそのまま書ける。拡大しても劣化せず、ファイルサイズも小さい。

- `content/figures/ai-overview.svg` — AI・機械学習・生成AIの包含関係
- `content/figures/prompt-flow.svg` — 入力から出力までの流れ
- `content/figures/screenshot-sample.svg` — 画面例（スクリーンショットの代用）

## 5. Service Workerの拡張

`content/` 以下へのリクエストを `ai-content-app-content-v1` キャッシュに保存する。
それ以外は従来どおり `ai-content-app-shell-v1` に保存する。

フェーズ1で分けた2つのキャッシュを、実際に機能する状態にする。フェーズ3で
「購入後にコンテンツだけ保存する／解約時にコンテンツだけ消す」処理を書くとき、
アプリ本体のキャッシュを巻き込まずに済む。

コンテンツはキャッシュ優先とする。一度取得したものはオフラインで確実に読め、
これはフェーズ3の「購入後にダウンロードしてオフライン閲覧」と同じ挙動になる。

なお `content/` 以下はインストール時の一括保存には含めない。フェーズ3では購入後に
初めて取得するものだからである。フェーズ2でも同じく、画面を開いた時点で保存される。
